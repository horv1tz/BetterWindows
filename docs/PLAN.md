# BetterWindows — план проекта

> Оболочка в стиле macOS поверх Windows 11: док, верхняя строка меню, Spotlight‑поиск,
> Launchpad, Mission Control, виджеты рабочего стола. Windows остаётся операционной
> системой, Explorer остаётся системной оболочкой — мы заменяем только видимые
> элементы интерфейса (как это делает Familiar Desktop).

Документ состоит из двух частей:

- `docs/PLAN.md` (этот файл) — что делаем, в каком порядке, какие риски, что нужно.
- `docs/ARCHITECTURE.md` — как именно это делается: стек, модули, Windows API, IPC.

---

## 1. Цель и границы

### Что хотим получить

Приложение для Windows 11 x64, которое после запуска:

1. прячет стандартную панель задач и показывает **док** внизу экрана (закреплённые и
   запущенные приложения, индикаторы, увеличение при наведении, автоскрытие);
2. показывает **строку меню** сверху (логотип‑меню, имя активного приложения,
   часы, батарея, Wi‑Fi, громкость, медиа, Control Center, календарь);
3. даёт **Spotlight‑поиск** по `Alt+Space` (приложения, файлы, калькулятор, настройки);
4. даёт **Launchpad** (сетка всех приложений) и **Mission Control** (обзор всех окон и
   виртуальных рабочих столов), горячие углы;
5. показывает **рабочий стол** с обоями, ярлыками и **виджетами** (погода, календарь,
   напоминания, медиа, батарея);
6. частично меняет **внешний вид окон** (кнопки «светофор» слева, скругления) —
   экспериментально;
7. хранит настройки, темы (светлая/тёмная) и локальные профили;
8. корректно **восстанавливает Windows** при выходе, падении и обновлении.

### Чего сознательно НЕ делаем

- Не заменяем `explorer.exe` как shell (слишком хрупко, ломается обновлениями Windows,
  теряются уведомления, тач‑клавиатура, Win+X и т.д.). Работаем **рядом** с Explorer.
- Не запускаем приложения macOS и не эмулируем macOS.
- Не копируем ассеты Apple (SF Pro, SF Symbols, иконки, обои) — только лицензионно
  чистые аналоги (Inter, Lucide/Fluent icons, свои обои).
- Не требуем прав администратора для повседневной работы.
- Omarchy‑плагин (Linux) — отдельный трек, после Windows‑версии (см. раздел 9).

### Целевая платформа

- Windows 11 22H2+ (x64). Windows 10 — «может работать», официально не поддерживаем:
  часть DWM‑API (цвет заголовка, скругления, backdrop) есть только в Windows 11.
- Один пользователь, без прав администратора. Окна приложений, запущенных от
  администратора, мы видим, но не можем ими управлять (ограничение UIPI) —
  документируем как известное ограничение.

## 2. Анализ референсов

| Проект | Стек | Что берём на заметку |
|---|---|---|
| **Familiar Desktop (Windows)** — закрытая альфа, $10 lifetime | .NET 8 Desktop + WebView2 | Та же связка, что выбираем мы. Функции: док, виджеты (погода, напоминания, календарь, медиа, батарея), поиск по `Alt+Space`, обои/ярлыки/темы, локальные профили, выход по `Ctrl+Alt+Q`, файлы открываются через Explorer. Подтверждает жизнеспособность «оболочка рядом с Explorer». |
| **Familiar Desktop (Omarchy plugin)** | Rust backend + QML/JS, Omarchy Quattro | Linux, Hyprland. Код с Windows не разделяется. Проект уже «retired», функциональность влита в Omarchy Quattro. |
| **Seelen UI** (AGPL‑3.0) | Rust + Tauri (WebView2) + Svelte | Самый полный аналог: тулбар, док, лаунчер, тайлинг, воркспейсы, виджеты, темы на CSS/JSON. Доказывает, что веб‑UI в WebView2 тянет док с анимациями. Код **нельзя** копировать (AGPL), но архитектуру и список фич — ориентир. |
| **ManagedShell** (Apache‑2.0, от авторов Cairo Shell) | .NET + WPF | Готовые сервисы: список задач (окон), область уведомлений (трей‑иконки), AppBar‑окна, шелл‑хелперы. Используется в Cairo Shell и RetroBar. Кандидат на зависимость для трея/задач/appbar. |
| **RetroBar / Cairo Shell** | .NET + WPF | Показывают, как спрятать штатную панель и жить рядом с Explorer; Cairo — как полностью заменить shell (мы так не делаем). |
| **TaskbarXI** (C++) | Win32 | Превращает штатную панель в «док». Нам не подходит как основа, но полезен как пример работы с `Shell_TrayWnd`. |
| **PowerToys Dock** (2026, Microsoft) | — | Microsoft сама тестирует верхний «док». Значит, идея востребована, а конкуренция вырастет — упор на цельность (док + меню + поиск + виджеты), а не на один док. |

Выводы:

1. .NET 8 + WebView2 — рабочий выбор: быстрая итерация визуала на HTML/CSS, общий
   движок с Seelen/Familiar, UI можно разрабатывать и тестировать в обычном браузере
   с мок‑бэкендом.
2. Самые «дорогие» и хрупкие части — область уведомлений (трей), виртуальные
   рабочие столы и внешний вид чужих окон. Их выносим в поздние фазы и за feature‑flags.
3. Хорошая практика: «один хоткей всё выключает» (`Ctrl+Alt+Q`), всегда можно
   вернуть штатную панель.

## 3. Стек (краткое решение, подробности в ARCHITECTURE.md)

| Слой | Выбор | Почему |
|---|---|---|
| Хост / сервисы | **C# / .NET 8**, TFM `net8.0-windows10.0.19041.0` | Доступ к Win32 и WinRT (медиа, сеть, питание) из одного кода |
| Окна‑хосты | **WPF** (окна без рамки, AppBar) + `WebView2` / `WebView2CompositionControl` | Зрелый хост WebView2, ManagedShell тоже на WPF |
| UI | **TypeScript + Vite + Svelte** (альтернатива — React) | Маленький бандл, быстрые анимации, темы на CSS‑переменных |
| P/Invoke | **Microsoft.Windows.CsWin32** (source generator) | Типобезопасный Win32 без ручных сигнатур |
| Трей / задачи / appbar | **ManagedShell** (оценить на 24H2; план B — своя реализация) | Экономит недели работы |
| Аудио | NAudio.CoreAudioApi | Громкость/устройства |
| Обновления / установщик | **Velopack** (MIT) + GitHub Releases | Setup.exe, дельта‑апдейты, без MSIX |
| CI | GitHub Actions `windows-latest` | Сборка .NET + Node, тесты, артефакты |

Рассмотренные альтернативы: Tauri/Rust (как Seelen) — хороший вариант, но
пользователь ориентируется на .NET; WinUI 3 / чистый XAML — ближе к «нативу», но
медленнее итерировать визуал и сложнее блюр/анимации; Electron — тяжелее по памяти.

## 4. Дорожная карта

Нумерация версий примерная. Каждая фаза заканчивается рабочим билдом, который можно
поставить и жить с ним.

### Фаза 0 — спайки и каркас (2–3 недели)

Цель: снять технические риски до написания «настоящего» кода.

- [ ] Каркас решения: `src/BetterWindows.Host` (WPF), `src/BetterWindows.Core`,
      `src/BetterWindows.Interop`, `ui/` (Vite), `tests/`, CI.
- [ ] Спайк A: прозрачное окно WPF + WebView2 со скруглениями и блюром, без белой
      вспышки, `WS_EX_NOACTIVATE` (клик по доку не отбирает фокус у приложения).
- [ ] Спайк B: AppBar (`SHAppBarMessage`) сверху и снизу на 2 мониторах с разным DPI.
- [ ] Спайк C: скрыть/показать `Shell_TrayWnd` (+ вторичные), пересчёт рабочей
      области, восстановление после перезапуска Explorer и после краша.
- [ ] Спайк D: список окон (`EnumWindows` + `SetWinEventHook` + shell hook),
      фильтрация как в панели задач, иконки exe/lnk/UWP в 256 px.
- [ ] Спайк E: ManagedShell на Windows 11 24H2/25H2 — трей‑иконки и задачи работают?
- [ ] Спайк F: снимки окон (`PrintWindow PW_RENDERFULLCONTENT` / `Windows.Graphics.Capture`)
      для Mission Control; DWM‑thumbnails поверх WebView2 (проблема airspace).
- [ ] Спайк G: «рабочий стол» за иконками (WorkerW‑трюк) на 24H2 — работает ли ещё.

Выход: ADR‑записи «что выбрали» в `docs/adr/`, прототипы в `spikes/` (не в main‑коде).

### Фаза 1 — MVP: док (v0.1)

- Док внизу: закреплённые + запущенные приложения, группировка окон по AUMID/exe,
  индикатор «запущено», клик = активировать/свернуть, ПКМ‑меню (закрепить, открыть
  новое окно, закрыть все, показать все окна).
- Увеличение при наведении (CSS, 60 fps), автоскрытие, размер, позиция (низ/лево/право).
- Запуск Win32, `.lnk` и UWP (`shell:AppsFolder\{AUMID}`).
- Скрытие штатной панели + восстановление при выходе/краше; хоткей
  `Ctrl+Alt+Shift+T` «показать панель Windows», `Ctrl+Alt+Q` — выход.
- Иконка в трее Windows (наша), автозапуск, единственный экземпляр.
- Настройки в JSON (`%LOCALAPPDATA%\BetterWindows\config.json`), горячая перезагрузка.
- Скрытие дока при полноэкранных приложениях/играх.
- Мультимонитор: док на основном мониторе (как в macOS — по умолчанию один).

Критерии приёмки MVP: день работы без перезапуска, RAM < 150 MB, idle CPU < 1 %,
панель Windows возвращается после любого выхода (включая `taskkill`).

### Фаза 2 — строка меню (v0.2)

- Верхний AppBar на каждом мониторе: меню‑«яблоко» (О программе, Настройки, Блокировка,
  Сон, Перезагрузка, Выключение, Выход), имя активного приложения с базовым меню
  (Quit = закрыть все окна, Hide = свернуть).
- Правая часть: часы с календарём‑поповером, батарея, Wi‑Fi/Ethernet, Bluetooth
  (статус), громкость (слайдер + устройство вывода), медиа «что играет» с управлением.
- Control Center (поповер): громкость, яркость (ноутбуки), Wi‑Fi/BT вкл‑выкл
  (через `ms-settings:`‑ссылки там, где нет API), тема светлая/тёмная, «Не беспокоить».
- Трей‑иконки сторонних приложений в строке меню — через ManagedShell (если спайк E
  успешен), иначе пункт «Показать скрытые значки» открывает штатную панель.

### Фаза 3 — Spotlight (v0.3)

- Оверлей по `Alt+Space`: приложения (из каталога), файлы (Windows Search через
  OLE DB `Search.CollatorDSO`), калькулятор, страницы настроек `ms-settings:`,
  веб‑поиск, недавние документы, команды оболочки (сон, выход).
- Нечёткий поиск, подсказки, предпросмотр файла, действия (открыть, показать в
  Explorer, копировать путь).

### Фаза 4 — Launchpad, Mission Control, горячие углы (v0.4)

- Launchpad: полноэкранная сетка всех приложений с поиском и папками.
- Mission Control: снимки окон, сгруппированные по приложению, клик — активировать;
  полоса виртуальных рабочих столов (публичный `IVirtualDesktopManager` для запросов,
  `SendInput` `Win+Ctrl+←/→` для переключения; внутренние интерфейсы — за флагом).
- Горячие углы и `F3`/`F4`‑подобные хоткеи; трёхпальцевые жесты — через настройку
  Windows «жесты → сочетание клавиш» (документируем для пользователя).

### Фаза 5 — рабочий стол и виджеты (v0.5)

- Собственный слой рабочего стола (обои, ярлыки‑ссылки на оригиналы, сетка),
  скрытие штатных иконок Explorer, обои через `IDesktopWallpaper` (по мониторам).
- Виджеты: часы/календарь, погода (Open‑Meteo, без ключа), напоминания (локально),
  медиа, батарея устройств (BT‑наушники/мышь через `Windows.Devices`), заметки.
- SDK виджетов: HTML‑виджет = папка с `manifest.json` + `index.html`, API через IPC.

### Фаза 6 — внешний вид окон и «Finder» (v0.6, экспериментально)

- Оверлей «светофор» (закрыть/свернуть/развернуть) слева на заголовке активных окон,
  следящий за окном через `EVENT_OBJECT_LOCATIONCHANGE`; скругления и цвет заголовка
  через `DwmSetWindowAttribute` (проверить кросс‑процессно).
- Глобальное меню приложения через UI Automation (только классические Win32‑меню,
  честно помечаем как experimental).
- Finder‑подобный обозреватель (только чтение и открытие; перемещение/удаление —
  через Explorer, как у Familiar).

### Фаза 7 — релиз 1.0

- Установщик и автообновление (Velopack), подпись кода (Azure Trusted Signing),
  winget‑манифест, онбординг «первый запуск», восстановление настроек по умолчанию.
- Локализация ru/en, темы, импорт/экспорт профилей.
- Документация пользователя, FAQ «что не работает и почему», политика обновлений
  Windows (поддерживаем N и N‑1 релизы).

## 5. Риски и как их гасим

| Риск | Вероятность | План |
|---|---|---|
| Обновление Windows ломает недокументированные вещи (`Shell_TrayWnd`, WorkerW, внутренние COM‑интерфейсы рабочих столов) | высокая | Всё недокументированное — за feature‑flag с graceful fallback; тест‑матрица на Insider‑сборках; «safe mode» при старте после сбоя |
| Антивирус/SmartScreen ругается на хуки клавиатуры/мыши | средняя | Подпись кода, минимум low‑level хуков (предпочитать `RegisterHotKey` и polling курсора), открытые исходники |
| Память WebView2 (каждое окно — процесс рендерера) | средняя | Одно `CoreWebView2Environment`, 3–4 WebView максимум, переходные UI (Spotlight/Launchpad/Mission Control) — в одном оверлейном окне |
| Клик по доку отбирает фокус, `SetForegroundWindow` не срабатывает | высокая (известная проблема) | `WS_EX_NOACTIVATE` для всех наших окон, активация чужих окон по проверенному рецепту (см. ARCHITECTURE) |
| Трей‑иконки: без штатной панели пользователь теряет значки приложений | высокая | ManagedShell‑хостинг трея; до него — хоткей/пункт меню «показать панель Windows» |
| Полноэкранные игры и док/меню поверх них | средняя | `ABN_FULLSCREENAPP` + собственная детекция, auto‑hide, «режим игры» (выключаем хуки) |
| DPI/мультимонитор с разным масштабом | средняя | PerMonitorV2, координаты только в физических пикселях в Core, окна на каждый монитор |
| Юридика: торговые марки и ассеты Apple | средняя | Своё имя, «macOS‑inspired» в описании, собственные иконки/шрифты, без «Finder»/«Spotlight» в названиях фич в релизе (внутри — можно) |
| Один разработчик, большой объём | высокая | Фазы с работающим билдом в конце каждой; MVP = только док |

## 6. Что нужно для старта

### Инструменты и окружение

- Windows 11 (23H2/24H2) машина для разработки + VM/второй ПК для тестов
  (обновления, чистый профиль, 2 монитора, 100 %/150 % DPI, ноутбук с батареей).
  Разработка в этом Linux‑контейнере невозможна: WPF/WebView2 собираются и
  запускаются только на Windows.
- Visual Studio 2022 (workload «.NET Desktop») или JetBrains Rider; .NET 8 SDK.
- Node.js 20+ (UI), pnpm/npm.
- WebView2 Runtime (на Windows 11 предустановлен; в установщик кладём Evergreen
  bootstrapper на случай Windows 10).
- Инструменты отладки: Spy++ / WinSpy (классы окон), Process Monitor, DebugView,
  Windows Performance Recorder (CPU/idle), Accessibility Insights (UI Automation).
- GitHub Actions (сборка на `windows-latest`), позже — сертификат подписи кода.

### Дизайн

- Дизайн‑система в Figma или просто в коде: токены (цвета, радиусы, тени, blur),
  светлая/тёмная тема, иконки (Lucide/Fluent UI System Icons), шрифт Inter.
- Собственные обои и иконка приложения.

### Знания/ресурсы, к которым придётся обращаться

- Win32: windows, hooks, appbar, DWM, shell (`IShellItem*`, `shell:AppsFolder`),
  COM (`IVirtualDesktopManager`, `IDesktopWallpaper`, `IApplicationActivationManager`).
- WinRT из .NET: `Windows.Media.Control`, `Windows.Networking.Connectivity`,
  `Windows.System.Power`, `Windows.Graphics.Capture`, `Windows.Devices.*`.
- WebView2: `CoreWebView2Environment`, виртуальный хост → папка, `PostWebMessageAsJson`,
  `WebResourceRequested` (отдача картинок из памяти).
- Исходники для изучения (лицензии позволяют читать): ManagedShell, RetroBar,
  Cairo Shell (Apache‑2.0), PowerToys (MIT, особенно `PowerToys Run`, `FancyZones`,
  `Peek`), Seelen UI (AGPL — только как референс поведения, не кода).

## 9. Трек «Omarchy‑плагин» (отдельно, позже)

Familiar для Omarchy — это Linux/Hyprland‑плагин на Rust + QML под Omarchy Quattro, и
он уже закрыт автором (функциональность влита в Quattro). С Windows‑кодом он не делит
ничего, кроме дизайна. Рекомендация:

- делать после Windows 1.0 или силами отдельного человека;
- общими держать только дизайн‑токены (`design/tokens.json` → CSS для Windows,
